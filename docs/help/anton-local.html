ANTON Local — overview & a guided tour

ANTON Local is the flagship of the suite: a desktop-class AI workspace for professional work, running entirely on your own machine. This page is the orientation tour — what it is, how it is laid out, who it is for, and how a single piece of work moves through it from start to finish.

1What ANTON Local is

ANTON Local is an AI-powered expert workspace for 55+ professional domains. It is the "brain" of the ANTON suite — the only application that talks to LLM providers, and the one the four phone apps connect back to. Technically it is a React 18 + TypeScript + Vite 6 front-end and an Express + Node 22 + PostgreSQL 16 back-end, both running on localhost.

What makes it more than a chat box is structure. Instead of a blank prompt, ANTON gives you roughly 260 expert modules grouped into 12 pillars — each module a pre-built workspace with a problem statement, tuned AI behaviour, a knowledge panel and output-format choices. You are never starting from nothing.

🧠

Structured, not blank

Every module opens with the problem already framed and the AI pre-tuned.

🔒

Local-first

Documents and the database stay on your machine; only LLM calls leave.

🔁

Multi-LLM

Claude is the default; OpenAI, Azure, Gemini, Mistral and Ollama also work.

🧭The design ethos — "start with the problem"

ANTON's guiding principle is "Start with the problem, not the solution." A general chat tool hands you an empty box and asks you to know exactly what to say. ANTON instead begins each module with a clear statement of the problem it solves and a behaviour already configured to solve it well. You can override everything — but if you simply click Run, the defaults are meant to produce excellent output. Think of the modules as a colleague's well-organised templates, not as a search bar.

2How to think about it

Two ideas explain almost every screen in ANTON Local.

  • Pillars are modes of mind, modules are tasks. A pillar is a whole way of working — expert consulting, education, market intelligence, automation. Inside a pillar, a module is one concrete job. You first choose the mode, then the task. The pillars page covers this in full.
  • The output is the artefact, the run is disposable. ANTON is built to produce a thing — a memo, a matrix, a board pack — not just a conversation. Every run yields Markdown plus a structured payload that can be re-rendered and exported many ways without re-running the model.
💡You do not need the command line

ANTON Local is deliberately built for professionals who are experts in their domain, not in software. After install, everything happens in the browser: pick, configure, run, export. The terminal is only for the one-time setup covered on Install & first run.

3The workspace layout

The window has three regions. Once you recognise them, ANTON is easy to navigate.

① The sidebar

Your navigation. It shows the active pillar, your favourites, and the module list for the current pillar, grouped by domain area. Pick a pillar, then a module.

② The workspace

The centre. The chosen module's problem statement, your input area, the knowledge source panel, the output-format picker, the thinking-level control and the Run button.

③ The output

Where the answer streams in live. After a run, the Transform panel re-renders it and the export controls produce Word, Excel, PDF, PowerPoint or Markdown files.

Above all of this sits the App Mode toggle — the control that switches between the 12 pillars. It is the single most important navigation element in ANTON, and the pillars page is devoted to it.

How it works The front-end — routes, lazy loading & state +

The React app is rooted in src/App.tsx, where every page is a lazy-loaded route (React.lazy() + Suspense) so the initial bundle stays small. Pages live in src/pages/ (60+ components); shared UI in src/components/; the sidebar in src/components/layout/Sidebar.tsx.

Global state is held in Zustand stores in src/stores/ — useSessionStore, useConfigStore, useSettingsStore and others. The active pillar is useSettingsStore.appMode. The 150+ module definitions live in src/lib/constants.ts; shared types in src/lib/types.ts. No Redux, no Context for global state.

4How a session works

Every piece of work in ANTON follows the same four-beat loop, whatever the pillar or module. Learn it once and the whole product opens up.

  1. Pick a module

    Choose a pillar from the App Mode toggle, then a module from the sidebar. The module opens with its problem statement and pre-tuned behaviour.

  2. Configure

    Add your input. Choose a knowledge source — Claude's Knowledge, online references, local folders or a combination. Pick one or more output formats. Set a thinking level if the task needs deeper reasoning.

  3. Run

    Click Run. The answer streams into the output area live via Server-Sent Events, with extended thinking shown when enabled.

  4. Transform & export

    The finished run is Markdown plus a structured payload. The Transform panel re-renders it — heatmaps, board decks, plain-language versions — and the export controls produce .docx, .xlsx, .pdf, .pptx files.

📌Example — one task, end to end

A compliance officer needs a gap assessment against a regulation. She picks the Work pillar, opens the Gap Assessment module, and sets the knowledge source to a Local Folder holding the firm's policy documents. She selects the Gap Scoring Matrix output format and a think_hard thinking level. She clicks Run; the matrix streams in. She then uses the Transform panel to produce an executive one-pager for the board and exports both the matrix to .xlsx and the one-pager to .pdf — without re-running the model once. Pick → configure → run → transform & export.

5Who it is for

ANTON Local is built for domain professionals aged 35–65 — consultants, lawyers, compliance officers, analysts, auditors, and experts across 55+ fields — who need reliable, structured, audit-defensible output from frontier LLMs, and who should not have to learn a command line or prompt-engineering to get it.

It is a good fit when…

  • You produce documents — memos, assessments, policies, briefings.
  • Your material is sensitive and should stay on your own machine.
  • You want consistent structure, not a different answer shape each time.
  • You value being able to export and re-render the same result many ways.

The design rules behind that

  • 14px+ minimum font, large readable text, clear labels.
  • Progressive disclosure — advanced controls are present but tucked away.
  • Fully keyboard navigable, full ARIA labels.
  • Three themes — light (default), dark, corporate.

How it works The server — routes, services & deployment modes +

The Express back-end is rooted in server/index.ts, where all routes are mounted. There are 157 route files in server/routes/, every one following the factory pattern — createXxxRoutes(db, anthropic?) returns a Router. Behind them sit 224 service files in server/services/, each single-responsibility — LLM clients, knowledge resolution, Markets (36 services), Risk Atlas (9), Portals (15), exports and infrastructure.

LLM responses stream to the browser over Server-Sent Events; Community messaging uses a WebSocket. server/services/claude-client.ts wraps the Claude API (streaming, adaptive thinking, web search) and prompt-builder.ts assembles the 7-layer prompt. Eight middleware layers cover auth, rate-limiting, CSRF and token budgeting.

Deployment mode is set by DEPLOYMENT_MODE in .env: solo (default, no auth) or team (JWT auth with viewer / analyst / admin roles). The database schema is identical in both — team mode simply activates the auth middleware.

7Best practices

✓ Do
  • Pick the pillar first, then the module — mode before task.
  • Trust the module defaults for a first run; tune only if needed.
  • Favourite the modules you use often so they sit at the top of the sidebar.
  • Use the Transform panel to re-render a result rather than re-running the model.
  • Match the thinking level to the task — quick for drafts, deeper for analysis.
✕ Don't
  • Don't treat ANTON like a chat box — start from a module, not a blank prompt.
  • Don't re-run a module just to get another export format — transform instead.
  • Don't ignore the knowledge-source panel; it decides where the AI's facts come from.
  • Don't expect every pillar to be equally mature — check Build status.
  • Don't forget you are the host — back the database up yourself.
★The one habit that makes ANTON click

Before every task, ask two questions in order: which pillar is this? and which module is the closest fit? Mode, then task. Once that becomes reflex, the rest of ANTON — knowledge sources, formats, transforms — is just refining a workspace that is already pointed at the right problem.
