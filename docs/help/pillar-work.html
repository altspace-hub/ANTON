The Work pillar — your expert modules

Work is ANTON's default pillar and the heart of the product: roughly 260 pre-tuned expert modules spread across about 59 professional domains. Each module is a structured workspace that already knows how an expert in that field thinks — so you can start with your problem, not a blank prompt box.

For: domain professionals 35–65 ~260 modules ~59 domain areas Default pillar

1What the Work pillar is

Open ANTON Local and, unless you switch pillars, you are in Work. It is the pillar most people spend most of their time in. Where a raw chat window asks you to describe the AI behaviour you want, a Work module arrives with that behaviour already configured: a problem statement, a tuned system prompt, sensible defaults for reasoning depth, and an output format chosen to suit the task.

That is the design philosophy in one sentence — "start with the problem, not the solution." Someone who simply picks the right module and clicks Run should get excellent output. Everything is overridable, but the defaults are the point.

◆

Every module ships with an expert system prompt and default knowledge, format and thinking settings.

▦

2How to think about picking a module

🧭The mental model

Don't ask "which AI feature do I need?" Ask "what is the deliverable, and who would normally produce it?" A module is named for an outcome — Gap Assessment, Policy Review, Alert Investigation, Pitch Deck Critique — not for a technique. Find the module whose name matches the thing you actually need on your desk, and the expert framing comes for free.

Three habits make module selection fast and reliable:

  • Match the deliverable. If you need a board memo, reach for a module that produces decision memos — not a general analysis module you then have to reshape.
  • Trust the area grouping. Modules sit inside a domain area for a reason: that area carries shared context the module inherits. A risk module run from the Risk area knows the risk vocabulary.
  • Read the problem statement first. Each module opens with a plain-language description of the problem it solves. If that statement doesn't describe your situation, it's the wrong module — keep looking before you start typing.
💡When no module fits exactly

Pick the closest one and adjust its inputs — most modules are broader than their name suggests. If you genuinely work across an unusual domain, Pathfinder reads your intent in plain language and routes you to the best-matching module automatically.

How it works The module registry and per-area patches +

The core module definitions live in src/lib/constants.ts — IDs, labels, default knowledge mode, default output format, default thinking level and the area grouping. The list is large, so additional modules are layered in through per-area patch files rather than bloating one file. That is why the suite docs describe the ~260 / ~59 totals as approximate: they are assembled from a core registry plus patches at load time.

Each module's expert system prompt is a file under server/areas/{area}/modules/. When you run a module the server resolves: the area context, then the module's own prompt, then the layers you chose (knowledge, persona, format). See Knowledge & prompts for the full 7-layer assembly handled by prompt-builder.ts.

4Running a module, step by step

The flow is the same for every one of the ~260 modules. Once you know it, you know all of them.

  1. Pick the module

    Choose the domain area, then the module whose problem statement matches your situation. Read that statement before going further.

  2. Describe your task

    Fill in the module's input fields — your context, the documents or scenario, the question. This is the only thing the defaults can't guess for you.

  3. Set the knowledge source

    Choose where the AI draws reference material: Claude's Knowledge, Online References, Local Folders, or Combined. The module's default is usually right — see Knowledge & prompts.

  4. Pick output format(s)

    Choose the deliverable shape — executive summary, action plan, gap matrix and so on. You select this before running.

  5. Choose a thinking level

    quick, think, think_hard or investigate. Deeper levels reason longer; the module's default suits most runs.

  6. Run, review, export

    Click Run; the answer streams in. Review it, iterate if needed, then export to docx / xlsx / pdf / pptx — see Output & export.

💡The defaults are pre-tuned for a reason

Every module already has a knowledge mode, an output format and a thinking level chosen by whoever built it. If you are new to a module, run it once on the defaults before changing anything. Override only what the first result tells you to override — that is faster than guessing the perfect configuration up front.

5Worked example — a Gap Assessment

You are a compliance officer at a mid-size payments firm and need to know how far your AML controls are from the incoming AMLR requirements.

📌Example — assessing AMLR readiness

You open the FCP area and pick the Gap Assessment module. Its problem statement — "measure a programme against a regulatory framework and score every gap" — is exactly your situation. You paste your current AML policy and procedure documents into the input, set the knowledge source to Combined (local-first) so your own documents lead, leave the output format on its default Gap Scoring Matrix, and bump the thinking level to think_hard because this needs careful reasoning. You click Run. ANTON streams back a matrix: each AMLR requirement, your current state, a RAG score and a specific remediation note. You export it to .xlsx with the RAG colours baked in, and hand it to your programme lead. The whole thing took minutes, and the structure is one a regulator would recognise — because the module was built by encoding how a financial-crime expert frames a gap assessment.

Notice what you did not do: you never wrote a system prompt, never described an output schema, never explained what a gap matrix is. The module carried all of that. For larger framework assessments, the dedicated Gap Assessment Wizard walks you through 8 steps with iteration support — the same idea, expanded into a guided flow.

How it works What a module run resolves on the server +

When you click Run, the request goes to ANTON's Express backend, where prompt-builder.ts assembles the final prompt from up to seven layers: system foundation → area context → org context & knowledge packs → the module's expert prompt → optional persona → skills → your chosen knowledge sources. The thinking level you picked becomes a transparency layer that configures reasoning depth.

For claude-opus-4-8 the level maps to an adaptive-effort setting (quick→low … investigate→max); for other models it maps to token budgets. The response streams back over Server-Sent Events. Every run yields Markdown and a structured JSON payload, which the renderer registry turns into your chosen export formats — see Output & export.

6Best practices

✓ Do
  • Read the module's problem statement before you start typing — it tells you if you have the right module.
  • Run on the defaults first; change settings only in response to the result.
  • Pick the output format that matches your real deliverable, before running.
  • Use Combined / local-first knowledge when your own documents must lead the analysis.
  • Raise the thinking level for genuinely hard reasoning; leave it low for routine drafting.
✕ Don't
  • Don't fight a module — if its framing is wrong for you, pick a different module.
  • Don't rewrite the system prompt; the module already encodes the expert framing.
  • Don't set every run to investigate — it is slower and rarely needed for drafting.
  • Don't paste confidential documents into a knowledge mode that allows web search if that matters to you.
  • Don't treat the first output as final — iterate; modules are built to be re-run.
★The Work-pillar habit

Build a short personal shortlist of the five or six modules you use most. Most professionals live inside a handful of deliverables; once you know which modules produce them and what their good defaults are, ANTON stops feeling like 260 tools and starts feeling like your own desk.
