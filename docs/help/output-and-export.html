Output formats & the export pipeline

ANTON does not just answer — it produces a deliverable. You choose the shape of the output before you run, and afterwards a library of renderers can transform that one result into a Word document, a slide deck, a risk heatmap or a plain-language rewrite. One run, many forms.

1What this page covers

Two stages turn a module run into something you can hand to someone.

Before the run, you pick an output format — one of 44 structured shapes like Executive Summary, Action Plan or Gap Scoring Matrix. The format becomes part of the prompt, so the AI writes into that shape rather than producing loose prose.

After the run, the transformation system takes over. Every run yields two things — readable Markdown and a structured JSON payload — and 16+ renderers can convert that into file exports, diagrams, alternative framings and review passes. You never re-run the model to get a new format.

2How to think about it

🧭The mental model

Think of a module run as casting a master. The output format you pick before running shapes the master itself — its structure, its sections, its level of detail. The renderers afterwards are presses: each stamps a copy of that master in a different material — DOCX, PDF, a Mermaid chart, a board deck. The expensive part (the AI's thinking) happens once; every export after that is a cheap, instant transformation.

Two ideas guide the choices:

  • Pick the format before you run. "Detailed Findings" and "Quick Briefing" are different documents — different length, depth and structure. The format steers the AI's writing, so choosing it after the fact means re-running. Decide the deliverable first.
  • Markdown is the source of truth. Every other format — DOCX, PDF, a heatmap — is derived from the Markdown plus the structured JSON. If something is wrong in an export, it was wrong in the run; fix the run, then re-export.
💡You can pick more than one format

Output formats are selected before running, and you can choose several at once — say Executive Summary and Detailed Findings. The AI produces both in one pass, which is far cheaper and more consistent than two separate runs.

3The 44 output formats

The 44 formats are organised into six categories. Each format carries its own prompt instructions, so the AI knows exactly what structure to produce.

📌Example — same task, two formats

You have just finished an AML gap assessment. For the compliance committee you want the numbers — you pick the Gap Scoring Matrix (Scoring), which produces a rated table the AI can later turn into a heatmap. For the board you want the story — you also tick Executive Summary (Strategic), a one-page narrative. One run, both deliverables, each in its proper shape.

How it works Where the formats are defined +

The 44 formats live in src/lib/output-format-definitions.ts — each entry is an object with an id, a category, a label and a block of prompt instructions describing the structure the AI must produce. When you select a format, those instructions are folded into the system prompt (alongside the seven layers — see Knowledge & prompts), which is why the format must be chosen before the run. Selecting several formats appends each instruction block.

4The transformation system

Every module run produces two artefacts, not one:

Markdown — the source of truth

The human-readable result. This is the default view and the canonical record. Every other format is derived from it.

Structured JSON — the machine payload

A Haiku-based extractor reads the Markdown and produces a structured payload (cached by content hash). This is what renderers like the heatmap or the Gantt chart need to draw something.

With those two artefacts in hand, the Transform Panel offers every renderer that fits. ANTON does not show all 16+ — it filters by the content type and the fields actually present, so you only see transformations that will work. Picking one is instant: no model call, no waiting.

💡Review passes are renderers too

Two of the most useful transformations are not exports at all. The devil's-advocate renderer re-reads your output looking for weaknesses and counter-arguments; the regulator's-eye pass reads it the way a supervisor would. Run them on any important deliverable before you send it — they catch the gap you stopped seeing.

5Exporting, step by step

  1. Choose the output format before running

    In the module, tick the format(s) you want. This shapes what the AI writes — pick the deliverable, not just the topic.

  2. Run the module

    The result appears as Markdown; the structured JSON is extracted in the background and cached.

  3. Open the Transform Panel

    It lists every renderer that fits this output — file exports, diagrams, reviews. Renderers that need fields your output lacks are hidden.

  4. Pick a transformation

    Choose a file export (.docx, .xlsx, …) or a visual renderer. It is produced instantly — no model call.

  5. Run a review pass, if it matters

    For anything you're about to send, run the devil's-advocate or regulator's-eye renderer first and read what it flags.

  6. Download or copy

    File exports download to disk; diagrams and HTML can be copied or saved. The Markdown stays as your canonical record.

6The renderer catalogue

The 16+ built-in renderers fall into four families.

FamilyRenderersWhat you get
File exports.docx · .xlsx · .pdf · .pptx · .fountainBranded Word docs, Excel with conditional formatting, typeset PDF, slide decks, screenplay format
DiagramsMermaid flowchart / Gantt / sequence / mindmap · SVG risk heatmapVisual structure drawn from the structured JSON
ReframingsExecutive one-pager · plain-language · board deck · standalone HTMLThe same content recast for a different reader or medium
Review passesDevil's-advocate · regulator's-eyeA critical second read that surfaces weaknesses and supervisory concerns
How it works The renderer registry +

Renderers are declared in server/services/renderer-registry.builtin.ts. Each registry entry states the content type it handles and the structured-JSON fields it requires; the Transform Panel filters the catalogue per session against the run's actual content type and available fields, so you only ever see transformations that can succeed. The file-export renderers themselves live under server/services/renderers/builtin/ — export-docx-renderer.ts, export-xlsx-renderer.ts, export-pdf-renderer.ts, export-pptx-renderer.ts, export-md-renderer.ts — with the diagram and review renderers in sibling folders (visualize/, review/, adapt/).

How it works Adding a new format +

The transformation system is built to be extended cheaply. Adding a new output renderer is, by design, one file plus one registry entry: write the renderer under server/services/renderers/ and declare it in renderer-registry.builtin.ts with its content type and required fields. Because every run already emits structured JSON, the new renderer immediately has data to work with — and the Transform Panel picks it up automatically wherever its fields are present.

7Best practices

✓ Do
  • Decide the deliverable, then pick the matching format — before you run.
  • Tick several formats in one run when you need more than one document.
  • Treat the Markdown as canonical; export from it, don't replace it.
  • Run a devil's-advocate or regulator's-eye pass on anything important.
  • Use the Scoring formats when you'll want a heatmap later — the renderer needs the structure.
✕ Don't
  • Don't re-run the model just to change format — transform the existing result.
  • Don't expect a renderer that isn't offered to work; it's hidden because the fields aren't there.
  • Don't fix an export by editing the file — fix the run and re-export.
  • Don't send a board pack without reading the regulator's-eye pass first.
  • Don't pick a format after running and wonder why the structure is loose.
★One run, many forms

The discipline that pays off: run the model once, well, with the right knowledge and the right format — then let the renderers do the rest. The thinking is expensive and the transformations are free. A team that internalises this stops re-running and starts re-rendering.
