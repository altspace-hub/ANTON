Getting started

Install ANTON & complete your first module

ANTON Local runs on your own computer. This page takes you from an empty machine to a finished piece of work — installing the prerequisites, running the setup wizard, getting an API key, and clicking Run on your first module. Allow about twenty minutes the first time.

1What you are installing

ANTON Local is the full ANTON desktop workspace — a React + TypeScript front-end and an Express + PostgreSQL back-end that both run on localhost. It is not a website you log into and not an app you download from a store. You install it once, on a machine you control, and it serves itself to your browser at http://localhost:5173.

Because it runs locally, ANTON needs a few supporting pieces installed alongside it: a JavaScript runtime, a package manager, and a database. The setup wizard handles almost all of this for you — the manual route is here for people who want to understand or customise each step.

2How to think about local-first

🧭The mental model

Think of ANTON as a workshop in your own building, not a desk you rent in someone else's office. The documents you feed it, the database it writes, the outputs it produces — all of that lives on your disk and never leaves. The only thing that crosses the network is the text of a prompt sent to an LLM provider so it can reason, and the answer that comes back. If that distinction matters for your work — and for a lawyer, compliance officer or analyst it usually does — local-first is the whole point.

Two consequences are worth holding onto, because they shape every later decision:

  • You are the host. There is no ANTON server watching over your data. That also means backups, updates and the database are yours to look after — see §9.
  • The API key is the one outbound door. Provider keys live server-side in .env and are never exposed to the browser. When you run a module, your prompt and its knowledge context go to Anthropic (or whichever provider you chose) and nowhere else. If you want a fully offline setup, point ANTON at a local Ollama model instead.
💡Good to know

If you point a module at Local Folders as its knowledge source, the contents of those files become part of the prompt sent to the LLM. Local-first means the files stay on disk — it does not mean their text is invisible to the model you chose. Knowledge-source modes are covered on the Knowledge & prompts page.

3Prerequisites

Four pieces of software. The first three are required; the fourth is optional and only matters for ANTON's knowledge-memory and vector-search features.

Node.jsv22 or newerThe JavaScript runtime that runs both the Vite front-end and the Express server.Required
pnpmv10The package manager ANTON's dependencies are locked against. Install with npm install -g pnpm.Required
PostgreSQL16 or newerThe database — every session, module run, pillar table and migration lives here.Required

💡Fast way to get Node on Windows

On Windows you can install Node in one line from a terminal: winget install OpenJS.NodeJS.LTS. On macOS, brew install node works equally well. Confirm with node --version — it must report v22 or higher before you go further.

4The automatic setup wizard

This is the recommended route. The wizard checks your environment, asks for an API key, sets up the database and installs everything. Once Node and pnpm are present (PostgreSQL too), the wizard does the rest.

  1. Clone the repository

    Open a terminal and run git clone <repo> && cd openexpert.

  2. Run the wizard

    On Windows, double-click setup-anton.bat or run it from a terminal. On macOS / Linux run powershell -ExecutionPolicy Bypass -File scripts/setup.ps1.

  3. Answer the prompts

    The wizard asks for your Anthropic API key (see §6), then auto-detects PostgreSQL and offers to create the anton user and anton database for you.

  4. Let it finish

    It installs dependencies with pnpm, checks for Ollama and pulls the embedding model if found, and initialises the database schema.

  5. Start ANTON

    Run pnpm run dev and open http://localhost:5173.

Behind the scenes the wizard performs exactly the steps in §5 — so if it stops partway, you can pick up the manual route from wherever it failed.

How it works What the setup wizard actually does +

The wizard is scripts/setup.ps1 (the Windows setup-anton.bat is a thin launcher around it). It verifies the Node and pnpm versions, prompts for ANTHROPIC_API_KEY and writes it into .env (copied from .env.example).

It auto-detects a local PostgreSQL service, then issues CREATE USER anton and CREATE DATABASE anton OWNER anton as the postgres superuser. Finally it runs pnpm install and pnpm run db:init, which applies server/db/schema.sql plus every pending migration in server/db/migrations-pg/ through the runner in server/db/init.ts.

5Manual setup, step by step

The same outcome, done by hand. Use this if you want to understand each step, are using an existing PostgreSQL server, or the wizard could not run.

  1. Clone and install dependencies

    git clone <repo> && cd openexpert, then pnpm install.

  2. Create the database

    Open psql -U postgres and run, in order: CREATE USER anton WITH PASSWORD 'anton'; then CREATE DATABASE anton OWNER anton; then \q.

  3. Install Ollama (optional)

    If you want knowledge memory and vector search, install Ollama and run ollama pull nomic-embed-text. Skip this and ANTON still works — only the memory features are dormant.

  4. Configure the environment

    Copy the template: cp .env.example .env. Open .env and set at minimum ANTHROPIC_API_KEY and DATABASE_URL — see the panels below.

  5. Initialise the database

    Run pnpm run db:init. It reads DATABASE_URL, applies the schema and runs every pending migration.

  6. Start the dev servers

    pnpm run dev starts Vite on port 5173 and Express on port 3001 together. For a production build, use pnpm run build then pnpm run start.

The two .env lines that matter

ANTHROPIC_API_KEYYour Claude key, e.g. sk-ant-.... Without it no module can run.
DATABASE_URLpostgresql://anton:anton@localhost:5432/anton — host, user, password and database in one string.

Optional .env keys

OPENAI_API_KEY, GOOGLE_API_KEY, MISTRAL_API_KEY and the Azure pair enable other LLM providers. PORT changes the Express port. ALLOWED_FOLDER_PATHS whitelists directories for the Local Folders knowledge mode. Every variable is documented in .env.example.

⚠Keep your keys server-side

The .env file is read only by the Express back-end — provider keys are never sent to the browser. Never paste a key into front-end code, a module field, or a commit. .env is git-ignored; leave it that way.

How it works Database commands & the migration runner +

pnpm run db:init applies server/db/schema.sql — the source of truth for every table — and then runs the migration runner in server/db/init.ts against everything in server/db/migrations-pg/ (161+ migrations as of v0.7.5).

To apply only newly-added migrations without re-initialising, use pnpm run db:migrate:pg. On Windows, the helper scripts/run-migration.cjs runs a single migration file directly. ANTON is PostgreSQL-only — there is no SQLite fallback.

6Getting an Anthropic API key

ANTON's default and most deeply integrated model is Anthropic's Claude (claude-opus-4-7). You supply your own key — ANTON does not resell access.

  1. Create an Anthropic account

    Go to console.anthropic.com and sign up or sign in.

  2. Add billing

    Claude API usage is pay-as-you-go. Add a payment method or a prepaid credit balance in the console.

  3. Create a key

    Under API Keys, create a new key. It starts with sk-ant-. Copy it once — the console will not show it again.

  4. Paste it into ANTON

    Give it to the setup wizard when prompted, or set ANTHROPIC_API_KEY=sk-ant-... in .env by hand.

💡You don't have to use Claude

ANTON supports six providers — Anthropic, OpenAI, Azure OpenAI, Google Gemini, Mistral and Ollama. Set the matching key in .env for any you want, and switch model per session in the UI. Ollama needs no key at all and runs entirely offline. Claude is simply the best-tuned default.

7First run — your first module

With pnpm run dev running, open http://localhost:5173. Here is what you will see and do.

  1. Pick a module

    In the sidebar, the Work pillar is selected by default. Browse the module list and choose something close to a real task — for example an Executive Summary or a Decision Memo.

  2. Read the problem statement

    Every module opens with a clear statement of the problem it solves and a pre-configured AI behaviour. You can run it as-is.

  3. Add your input

    Type or paste what you want analysed. Leave the knowledge source on Claude's Knowledge for now — other modes are on the Knowledge & prompts page.

  4. Choose an output format

    Pick one of the 40+ formats before running. The default is sensible — you can change it later.

  5. Click Run

    The answer streams in live via Server-Sent Events. When it finishes you can transform it or export to Word, Excel, PDF or PowerPoint — see Output & export.

📌Example — a five-minute first win

You open the Decision Memo module in the Work pillar. The problem statement already frames it as "produce a board-ready memo recommending a course of action". You paste three paragraphs about a vendor choice you are weighing, leave the knowledge source on Claude's Knowledge, pick the Decision Memo output format, and click Run. Twenty seconds later you have a structured memo — options, recommendation, risks — that you export to .docx with ANTON branding. That is the whole loop: pick a module, configure, run, export.

8Solo vs team deployment

ANTON runs in one of two modes, set by the DEPLOYMENT_MODE variable in .env.

ModeWho it is forAuthentication
solo defaultOne person on one machine — most installs.None. You open the workspace and start working.
teamA shared instance several people reach.JWT-based login with roles — viewer, analyst, admin.
💡Start solo

Unless you are deliberately standing up a shared instance, leave DEPLOYMENT_MODE on solo. You can switch to team later — the database does not change, only the auth middleware activates. Team mode also pairs with the ANTON Companion phone app and its approvals inbox.

9Best practices

✓ Do
  • Use the setup wizard first — fall back to manual only if it stops.
  • Confirm node --version reports v22+ before anything else.
  • Keep .env out of version control — it is git-ignored by default.
  • Back up the PostgreSQL anton database regularly — you are the host now.
  • Start in solo mode; move to team only when you actually share the instance.
✕ Don't
  • Don't paste an API key into module fields or front-end code — keys live in .env only.
  • Don't skip pnpm run db:init — ANTON will not start without its schema.
  • Don't use an older Node — v20 and below will fail the version check.
  • Don't assume Local Folders content is private from the LLM — local-first means files stay on disk, not unseen.
  • Don't commit a database snapshot containing client documents to a shared repo.
★The shortest honest path

Install Node, pnpm and PostgreSQL. Run setup-anton.bat. Paste your sk-ant- key. Run pnpm run dev. Open the workspace, pick a module, click Run. Everything else on this page is detail you can return to. When you are ready for the guided tour of the workspace itself, head to ANTON Local — overview & tour.
