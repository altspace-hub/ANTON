# Security Audit Guide

## Overview

The FCP Workbench implements automated dependency vulnerability scanning and license compliance checking to ensure secure and legally compliant operation.

## Running Security Checks

### Quick Audit
```bash
npm run audit
```
Runs npm's built-in vulnerability scanner at moderate severity level.

### Auto-Fix Vulnerabilities
```bash
npm run audit:fix
```
Automatically updates packages to fix vulnerabilities where possible without breaking changes.

### Full Security Audit
```bash
npm run audit:full
```
Comprehensive audit including:
- Vulnerability scanning
- Outdated package detection
- License compliance checking

### Generate Vulnerability Report
```bash
npm run security:report
```
Creates a detailed `vulnerability-report.json` with:
- Severity breakdown (critical, high, moderate, low, info)
- Package-specific vulnerability details
- Fix availability status

### Check Package Licenses
```bash
npm run licenses
```
Quick summary of all package licenses.

```bash
npm run licenses:full
```
Detailed CSV report of all licenses.

```bash
npm run licenses:report
```
Generates `LICENSES.csv` and flags non-standard licenses.

### Check Outdated Packages
```bash
npm run outdated
```
Lists packages with available updates.

## Automated CI/CD Checks

The `.github/workflows/security.yml` workflow runs automatically:
- On every push to main
- On every pull request
- Weekly on Monday at 2am UTC
- On-demand via GitHub Actions UI

The workflow:
1. Installs dependencies
2. Runs security audit
3. Generates vulnerability report
4. Checks licenses
5. Uploads reports as artifacts

## Dependency Update Automation

### Dependabot (GitHub)
Configured in `.github/dependabot.yml`:
- Weekly scans every Monday
- Groups patch updates together
- Groups minor updates together
- Auto-creates PRs for security updates
- Limit: 5 open PRs at a time

### Renovate (Alternative)
Configured in `renovate.json`:
- Scans before 3am every Monday
- Groups updates by type (patch/minor)
- Labels PRs with "dependencies"

Choose one automation tool, not both.

## Vulnerability Response Process

### Critical Vulnerabilities
1. Automated alert triggers
2. Review within 4 hours
3. Test fix in dev environment
4. Deploy to production within 24 hours
5. Document in changelog

### High Vulnerabilities
1. Review within 24 hours
2. Test fix within 3 days
3. Deploy within 7 days
4. Full test suite verification

### Moderate/Low Vulnerabilities
1. Review monthly
2. Bundle with regular maintenance
3. Include in quarterly release

## License Compliance

### Allowed Licenses (Auto-Approved)
- MIT
- Apache-2.0
- BSD-2-Clause, BSD-3-Clause
- ISC
- CC0-1.0 (public domain)
- Unlicense

### Restricted Licenses (Review Required)
- GPL-3.0 (dev dependencies only)
- Any proprietary licenses
- Any copyleft licenses in production

### License Review Process
1. Run `npm run licenses:report`
2. Review flagged packages
3. Document exceptions in `EXCEPTIONS.md`
4. Get senior developer approval

## Manual Security Checks

### Before Adding New Dependencies
```bash
# Check for known vulnerabilities
npm info <package-name> --json | grep -i vulnerabilities

# Check license
npm info <package-name> license

# Check maintenance status
npm info <package-name> time

# Check bundle size impact
npx bundle-phobia <package-name>
```

### Quarterly Dependency Review
1. Run full audit: `npm run audit:full`
2. Review outdated packages: `npm run outdated`
3. Check license compliance: `npm run licenses:report`
4. Review dependency tree: `npm ls --all`
5. Identify unused dependencies: `npx depcheck`
6. Update documentation

## Reports and Artifacts

### vulnerability-report.json
Generated by `npm run security:report`
- Timestamp
- Vulnerability summary by severity
- Total dependencies
- Package-specific details

### LICENSES.csv
Generated by `npm run licenses:report`
- Package name
- Version
- License
- Repository URL

### audit-report.json
Generated by `npm run audit:full`
- Raw npm audit output
- Used for parsing and analysis

## Security Metrics

Monitor these metrics:

- Time to fix (critical/high)
- Outdated packages count
- License compliance exceptions
- Average dependency age
