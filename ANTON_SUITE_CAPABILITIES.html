ANTON Suite — Capabilities & Architecture

A complete fly-over of the ANTON ecosystem: one local-first desktop workspace and four phone apps, the protocols that bind them, and an honest map of what is built, what is stubbed, and what is still spec.

5 applications 12 pillars ~260 expert modules 38 languages Local-first · privacy by design

◆The five apps

ANTON by openEXPERT is an AI-powered expert ecosystem. One is a full desktop-class workspace; four are focused, phone-only companions. Every app stores its data on the user's own device — only LLM API calls and explicitly-chosen network actions ever leave the machine.

The connective tissue
What binds the suite

The ANTON Mesh relay, the FutureChain SDK, the Ed25519 pairing ritual, the futurechain:pay URI contract and the ANTON Agent Protocol — all anchored on Ed25519 identity with no central PKI.

Two ways phones reach a desktop

  • Direct HTTPS — Companion talks straight to an ANTON Local endpoint on the LAN or a public URL.
  • Mesh relay — when the instance isn't publicly reachable, Noise-IK ciphertext is bounced through the relay, which can never read it.

One identity primitive everywhere

  • Ed25519 long-term keys anchor every app and instance.
  • Contact hash ANTON-XXXX-XXXX-XXXX-XXXX is the shareable, privacy-preserving address.
  • No central PKI — trust flows through QR exchange and signed audit trails.

The flagship application: an AI-powered expert workspace for 55+ professional domains. React 18 + TypeScript (strict) + Vite 6 front-end; Express + Node 22 + PostgreSQL 16 back-end; Tailwind 4; Zustand state. It runs entirely on localhost — documents never leave the machine, only LLM calls do.

Design ethos"Start with the problem, not the solution." Every module opens with a problem statement and pre-tuned AI behaviour; click Run and the defaults already produce excellent output.
Primary usersDomain professionals aged 35–65 — consultants, lawyers, compliance officers, analysts — who need reliable, structured, audit-defensible AI output without a command line.
Deployment modessolo (default, single-user, no auth) or team (JWT auth, roles: viewer / analyst / admin).

Server architecture

Routes

157 route files in server/routes/. All follow the factory pattern: createXxxRoutes(db, anthropic?) → Router, mounted in server/index.ts.

Services

224 single-responsibility service files — LLM clients, knowledge resolution, Markets (36), Risk Atlas (9), Portals (15), exports, infrastructure.

Connectors

4 adapters — API, database, filesystem (path-whitelisted), script (no shell injection). Credentials decrypted from an encrypted vault.

Middleware (8): auth (JWT/session), rate-limit (4 limiters), CSRF, token budget, audit queue, app-auth (device certs), relay-auth, role gates. Streaming: Server-Sent Events for LLM responses; WebSocket for Community messaging and focus tracking.

Knowledge sources & the 7-layer prompt

4 knowledge source modes

  1. Claude's Knowledge — built-in + optional web search.
  2. Online References — paste URLs; the server fetches & extracts text.
  3. Local Folders — index whitelisted directories on the machine.
  4. Combined — merge with priority rules (local-first / AI-first / merged).

7-layer prompt assembly

Every request is built by prompt-builder.ts from layered context: system foundation → area context → org context & knowledge packs → module expertise → optional persona → skills → knowledge sources → transparency (thinking-level config). 8+ named expert personas and 10+ audience proxies (board, regulator, journalist…) can be layered on.

The Risk Atlas — deterministic risk engine

A universal seven-stage threat-path methodology generalising the CASP BWRA approach. The pattern is deterministic engine + LLM rationale: the AI never decides the scores, only the words around them — so the register is audit-defensible by construction.

The 7 stagesExposures → Threat paths → Vulnerabilities → Inherent risk (= max E,T,V) → Controls (Strong/Adequate/Weak, worst-of) → Residual (= inherent − reduction, clamped 1–5) → Appetite (5×5 grid).
Data model18 tables (risk_atlases, atlas_threat_paths, atlas_controls, atlas_residual_scores…) across migrations 125–129.
Industry packs25 composable .anton overlays — industry, FCP-domain (AML/CFT, sanctions, fraud, ABC, market abuse, tax-evasion facilitation, export controls) and universal-core, with parent inheritance.
Integrity rules6 Compliance-as-Code checks (ATLAS-INT-001…006) surface live findings — residual ≥4 with no appetite, a Strong control with no evidence, etc.
ExportsBoard-pack DOCX, threat-path PDF, heatmap SVG, .anton bundle.

Output formats, renderers & export

44 output formats in 6 categories — Strategic (executive summary, decision memo, board pack…), Analytical (detailed findings, regulatory comparison, audit report…), Operational (action plan, policy document, RACI…), Scoring (gap matrix, maturity assessment…), Communication (briefings, training material, presentations…) and Planning (compliance calendar, budget estimate…).

Every run produces Markdown (the source of truth) plus a structured JSON payload. 16+ post-hoc renderers then transform it: the 5 file exports (.docx, .xlsx, .pdf, .pptx, .fountain), Mermaid flowchart / Gantt / sequence / mindmap, an SVG risk heatmap, an executive one-pager, a plain-language version, a board deck, a standalone HTML file, and "devil's advocate" / "regulator's-eye" review passes.

2ANTON Companion — your instance, in your pocket

▲
ANTON Companion
src/app/ · android/ · PWA + Capacitor 8.3 · teal theme

The mobile surface of an ANTON Local instance. It is built for the professional who needs to respond to urgent work items, approve actions and run AI-assisted research away from the desk — while the organisation keeps control through the pairing ritual.

What it does

Pairing & multi-instance

  • Ed25519 enrollment ritual — scan a QR, the phone mints a fresh keypair into the Keychain/Keystore, signs the challenge, receives a device certificate.
  • Pair with several ANTON Local instances; a Wallet-card-style switcher makes the active one unambiguous.
  • Two transports — direct HTTPS, or Noise-IK mesh via the relay.

Approvals — the enterprise wedge

  • A severity-sorted checkpoint inbox surfacing pending decisions from the instance.
  • Biometric re-confirm on critical / high items.
  • Responses are Ed25519 signed-envelopes with replay-protected nonces.

Capture, voice & push

  • Camera / library / share-sheet capture, resized to 2048px before upload.
  • Full-screen hold-to-talk voice mode with live captions and barge-in.
  • APNs / FCM / web-push — payloads carry only an event id, severity and opaque title, never confidential content.

Full workspace reach

35+ screens mirror the desktop pillars — Chat, Tasks, Schedule, Search, Markets, Radar, Missions, My Work, Community, Portals, Wallet, Work Modules, School. A "Standard mode" offers a simplified 4-tab variant for NGO and plain-language deployments.

Identity lives in src/app/services/identity.ts; the paired-instance store and race-free switcher in instances.ts; approvals in checkpoints.ts. Server side: app-enrollment-service.ts and the /api/app/* routes. App id com.futurechain.anton.companion.

3ANTON Comm — standalone communication & money

●
ANTON Comm
src/comm/ · android-comm/ · Capacitor 8.3 · navy theme

A peer-to-peer communication app that needs no ANTON Local instance. It bootstraps its own Ed25519 identity, talks to peers end-to-end encrypted through the relay, and carries a full FutureChain wallet with a jurisdiction-aware tax engine.

Capabilities

Messaging & social

  • E2E-encrypted chat (HPKE / X25519) — reactions, edits, deletes, polls, voice notes, media, location share, disappearing messages, receipts.
  • Wassup — an ephemeral status feed (text + image, 24h default), likes and comments, fanned out over the chat layer to contacts only.
  • Events — a local calendar with invitations and RSVPs carried over E2E chat.
  • Portals — discover ANTON portals via the relay registry, then invoke capabilities directly on the owner's instance.

Wallet, tax & fraud

  • A FutureChain secp256k1 wallet — send, receive, swap; an on-device transaction ledger.
  • Tax engine — jurisdiction-aware position & annual reports via @futurechain/sdk/tax; cost-basis methods, holding-period relief, K4 / CSV export.
  • Money profile — a self-declared baseline (DOB, nationality, occupation, source of funds, expected spend).
  • Light fraud engine — the same 9-rule deterministic check as ANTON Pay, run before each payment is confirmed.
~18 screens, ~30 services. Relay client speaks a 5-byte framed WebSocket protocol (HELLO_COMM → DELIVER_COMM) to wss://relay.futurechain.eu. Data sits in an IndexedDB v3 schema. App id com.futurechain.anton.comm.
Comm currently ships only English and Swedish locale catalogues. Non-en/sv users see English for the whole app — translating Comm into the other 36 languages is a known, separate effort.

4ANTON Business — the merchant app

⟪
ANTON Business
src/business/ · android-business/ · Capacitor + Vite + React · blue #3070C7

A phone-only, no-backend tool for small and medium merchants — retailers, restaurants, event sellers, consultants — to accept FutureChain payments by showing a QR code. Designed for merchants who are not crypto-savvy.

How it works

Two sale modes

  • Simple — tap an amount on the keypad, show the QR.
  • Extended — build a cart from a pre-set item catalogue, with per-item VAT and discounts, then show the QR.

Receipt ledger

Every sale becomes a kvitto with gap-free Bokföringslagen 5 kap. numbering (K-000001…), status tracking, full VAT detail, exportable to PDF or JSON.

The QR it produces

A futurechain:pay URI carrying the merchant receive address, the amount in micro-FTC, an 8-char merchant id, a 12-char order id, the ADR-004 v1 reference, optional VAT/discount, a 15-minute expiry — and the merchant's ISO 20022 creditor party (cn/cc/cct/cst/cpc), added so the payer can build a complete PACS.008 record.

Onboarding collects legal name, org number, address, VAT status and country. Settings (ported from Comm) cover wallet, appearance with 8 accent colours, backup/export, language and reset. 38 languages. Build: build:business:cap → copy dist/business/ → gradlew assembleDebug.

5ANTON Pay — the customer payments app

☀
ANTON Pay
src/pay/ · android-pay/ · Capacitor + Vite · sunrise-orange #C97220

The newest app: a focused, phone-only payments app for private people who just want to pay merchants — without the full ANTON Comm experience. Scan, review, check for fraud, confirm. All on-device.

The payment flow

  1. Onboard once — a wallet (Ed25519 keypair) is created up front; identity entry is optional.
  2. Scan — the camera reads a merchant's futurechain:pay QR (manual paste fallback exists).
  3. Review — the decoded payment is shown: FTC amount + estimated SEK, merchant, purpose, VAT, a live expiry countdown, and an expandable ISO 20022 payment detail panel.
  4. Fraud check — the light fraud engine scores the payment and lists any signals; a warning level arms a two-step "Pay anyway" confirm. It is always advisory — it never blocks.
  5. Confirm — the payment is recorded locally with a full PACS.008 draft assembled from the saved identity and the scanned creditor.

The light fraud engine

A pure, deterministic, on-device scorer — no LLM, no network, no I/O. It compares the pending payment against two baselines: the self-declared money profile and the derived behaviour profile.

SignalFires when…

above-typicalMuch larger than the declared typical payment size

Signals are weighted (info 8 / caution 22 / warning 45), summed and capped at 100. The Activity Review screen shows the user their own pattern and every flagged payment after the fact.

Services: payment.ts, payment-identity.ts, pacs008-draft.ts, money-profile.ts, behavior-profile.ts, fraud-engine.ts — all with unit tests. 38 languages. App default accent: sunrise orange.

↔ANTON Mesh & the relay

A WebSocket relay broker that replaces Cloudflare Tunnel. It is the transport rail when a phone cannot reach an ANTON Local instance directly — and the discovery rail for Comm messages and portals.

Locationrelay/ — ~5,900 lines of TypeScript, Apache-2.0, fully self-hostable (Docker / systemd / bare Node).
Cipher suiteNoise_IK_25519_ChaChaPoly_BLAKE2b — ChaCha20-Poly1305 AEAD, X25519 ephemeral DH, Ed25519 long-term identity.
What it can doMatch connections by instance_id and forward opaque ciphertext. Observe metadata (who connects when). Cause denial of service.
What it cannot doDecrypt traffic, impersonate an instance (binding signature), or misroute (direction-tag + instance-id checks).
StatusBUILT Phase 2 reference implementation complete, threat model peer-reviewed.

The same relay process also exposes an HTTP /v1/portals/* registry for portal discovery and routes the Comm app's E2E message frames — a frame-type byte distinguishes instance traffic from Comm traffic.

↔Pairing & enrollment ritual

How a phone becomes trusted by an ANTON Local instance — an Ed25519 ritual with no central authority.

  1. The admin opens "Connect a device". The instance issues a 60-second-TTL enrollment package: its Ed25519 + X25519 public keys, a self-binding signature, relay endpoints, a nonce and an optional 6-digit out-of-band code.
  2. The phone scans the QR, generates a fresh Ed25519 keypair, and stores the private key in the biometric-protected Keychain / Keystore.
  3. The phone signs ${token}.${nonce}.${publicKey} and POSTs to /api/app/enrollment/complete with the confirmation code.
  4. The server verifies signature and code, then issues a device certificate and a 30-day session token. The phone biometric-locks the credentials.
At rest, the instance private key is AES-256-GCM encrypted in instance_identity.privkey_encrypted when INSTANCE_KEY_ENCRYPTION_KEY is set. The contact hash format ANTON-XXXX-XXXX-XXXX-XXXX is shared by every app in the suite.

↔The payment flow, end to end

The futurechain:pay URI is the contract between merchant and customer apps. Business encodes it; Pay and Comm decode it.

       ▼                                            decode + validate

The ref field carries the ADR-004 v1 reference — merchant id, order id, purpose (RETAIL/RESTAURANT/EVENT/SERVICE/REFUND), and optional item count / VAT / discount. On the payer side, the purpose is mapped to an ISO 20022 external purpose code (RETAIL→GDDS, RESTAURANT/SERVICE→SCVE, EVENT→OTHR, REFUND→REFUND) when the PACS.008 draft is assembled. Settlement itself is bilateral between the merchant and Safello — the apps only keep local records.

↔Agent Protocol & portals

ANTON Agent Protocol (AAP)

A symmetric instance-to-instance protocol — wire format v1 locked. WebSocket over wss:// at /aap/v1, advertised via mDNS. After an Ed25519-signed HELLO/WELCOME handshake and an X25519 ECDH, peers exchange AES-256-GCM-encrypted .anton bundles — contact bundles, evidence packs, market theses, Risk Atlas packs, portals. Every message carries a replay-protected nonce.

Portals & the registry protocol

Portals are user-built ANTON web spaces that double as machine-readable endpoints. The registry protocol adds deterministic canonical JSON, signed envelopes and homoglyph defence; a registry client submits portals to the relay-hosted registry and verifies them against a signed transparency log. Local portals are complete; cross-instance public discovery has a 6-phase roadmap with a legal review gating launch.
