Companion App · Visual Evolution v2 · for Claude Code

The bones are right. The build isn't matching the design yet.

Looking at the rendered Android screenshots side-by-side with the v3 design files in the repo, the gap is implementation, not direction. Status bar collisions, raster emoji icons standing in for the custom Ico set, weak hierarchy on Home, half-empty Capture, and a logo system that hasn't been drawn yet — these are all fixable in one focused pass. This document pairs each problem in the screenshots with the exact target it should hit.

01 · What the screenshots show

Eight concrete problems, ranked.

Every issue below is visible in the six screenshots you sent. Each one has a single, small fix.

01 · Top of every screen
The instance name collides with the Android status bar.
"Anton Test 12:51" overlaps the system clock and notification glyphs. The app is drawing edge-to-edge but isn't honoring env(safe-area-inset-top). The status dot floats outside the box. It looks broken before the user has even read a word.
Fix → Add padding-top: max(12px, env(safe-area-inset-top)) to InstanceTopBar; never let it draw under the system area.
02 · More menu, Quick Actions, Capture
Stock emoji are standing in for the icon system.
The 13-tile More grid uses raster emoji (briefcase, calendar, satellite, money bag). Quick Actions has a microphone emoji and a green check. Capture uses a camera emoji and a framed-picture emoji. The design system specifies a custom 1.75-stroke Ico set — emoji break the linework and look like clip-art on a serious tool.
Fix → Replace every emoji with its Ico twin. Render module tiles as monogram glyphs (see §3).
03 · Home greeting
The greeting card has nothing to lead with.
"Good afternoon, Daniel" hangs alone above four flat tiles, then a single chat session, then a wall of empty linen. The most-used surface in the app gives the user no clear next action — and pending approvals (the entire reason this app exists) aren't surfaced.
Fix → Replace the greeting block with a "Waiting for you" hero card. Demote quick actions to a 2×2 below it.
04 · Capture screen
Two emoji-tiles in a 92% empty canvas.
"Take photo" and "Pick from library" sit at the top of a near-blank screen. Nothing tells the user what the capture is for, where it lands, or what ANTON will do with it. This is the highest-leverage interaction in the app and currently feels like a default Android picker.
Fix → Live camera viewfinder fills the screen; preset chips above (Receipt · Whiteboard · Document · Voice note); destination is named ("Goes to your ANTON · Sanctions Advisory").
05 · Chat with ANTON
The first reply is a wall of bullet questions.
ANTON's first response is a generic "what are you working on" / "what context matters" / "what format do you need" interrogation. It feels like a meta-prompt. Plus the message bubble has no avatar, no timestamp on the right, and the composer is glued to the keyboard with a pale unreadable disabled state.
Fix → Replace the cold-start template with a contextual greeting using the user's recent activity. Add a small ANTON avatar dot. Compose as a card, not a wall of text.
06 · Bottom nav (Pro)
Two tabs share the same icon.
"Approvals" and "Capture" both render with a tray-style inbox glyph. The active-tab indicator is a thin top line on Home and Capture but the labels still read identically-weighted. With the FAB punching through the nav, visual hierarchy is muddy.
Fix → Approvals = shield-check; Capture = camera-aperture. FAB sits above the tab row with a clear shadow gap, not flush with it.
07 · Bottom sheets
Sheets cover content with a flat grey wash.
When the More menu or Quick Actions opens, the backdrop is a uniform grey that blurs nothing and reveals nothing. The sheet itself is corner-rounded but has no drag-handle visible against the background, no shadow, no separation. Looks like a debug overlay.
Fix → Backdrop becomes a 8% ink scrim with subtle backdrop-blur(4px). Sheet gets a 1px hairline + 22px top radius + a 3px × 36px gray drag handle.
08 · Brand mark
There is no companion-app logo yet — only "ANTON" set in the body font.
The instance-pill in the top-left ("● Anton Test") is the only branding visible, and it's a status dot plus a name string. There's nothing for splash, push notif badge, app icon, share-sheet thumbnail, or the empty-state glyph in the share target. Claude Code will need a real mark.
Fix → Use a single-letter monogram system: bold "A" in a rounded-square, teal on linen. Works at 16px (favicon) through 1024px (app icon). Spec in §3.

Home — give the user one clear thing.

03 · Mark + module glyphs

One letter. Drawn once. Used everywhere.

You don't need an illustrated logo for a remote-control app. A geometric monogram is sturdy at every size, holds the brand teal cleanly, and replaces every emoji-tile in one stroke. Same construction logic generates module glyphs (MI, KB, RA…) so the More grid stops looking like a clip-art page.

08 · Hands off

What to leave alone.

The redesign should not pretend everything is broken. Several things are right — and changing them now would be churn.

KEEP
The Editorial direction.
Warm linen canvas, restricted teal, mono labels for metadata — this is the right direction. The redesign here amplifies it; it doesn't replace it.
KEEP
Pro / Standard mode split.
Two modes, two densities, one data layer — this is the headline a11y feature. Standard still needs its own visual rhythm (calendar-style time-blocks on Home, mailbox-style messages) but the framework is right.
KEEP
8 personal accent colors.
Locked status colors + runtime-swappable accent is the right model. The accent applies to the hero card border, primary CTAs, live dots, and section markers — never to status (red/gold/green/blue stay locked).
KEEP
Monospace-for-metadata rule.
JetBrains Mono on timestamps, hashes, instance IDs, transport ("LAN"), token counts, severity labels. Inter on everything else. Don't relax this — it's what makes ANTON look like an instrument and not a chat app.
